# Rabbit · Product UI & UX Design Spec

> 面向独立授课者的预约与课时管理。老师端 iOS · 学员端 Web。  
> 视觉以新 logo 为源，产品气质对标 Things：克制、精致、完成感明确。  
> 本文件是 **UI/UX 的权威约定**；功能与规则仍以 `docs/mvp.md` 为准。冲突时：**规则听 mvp，观感听本文**。

**版本：** 0.1 · 2026-09-22  
**Logo 源文件：** 仓库外品牌资产 / App Icon（白兔 + 绿日历勾 + 黄铅笔）

---

## 1. 设计意图

Rabbit 解决的是「排课和课时账从微信里搬出来」。界面要让老师觉得：清楚、可信、少操作；让学员觉得：打开就能约，不像在学一个新工具。

**对标 Things，不是抄 Things。** 借的是：大留白、清晰层级、列表为主、完成动作有仪式感、几乎无装饰噪音。不借：黄主题、GTD 信息架构、桌面端复杂视图。

**Logo 进产品的方式：** 把圆角、干净色块、绿色「完成」、黄色「书写/创造」抽成系统；兔子的俏皮只出现在空状态、成功瞬间、App Icon——**日常列表保持安静**，避免整页卡通化。

一句话：

> 看起来像一本整理过的课表，而不是一个玩具；摸起来像 Things，认得出是 Rabbit。

---

## 2. 产品 UX 原则（写界面时先过一遍）

1. **列表是真相，卡片是重点。** 今天的课、学员、课时流水都以列表承载；下一节课、待处理、主 CTA 才用卡片抬高。
2. **完成比浏览更重要。** 「完成课程」、学员约成、勾选可用日——交互终点要落在明确的完成态（绿勾 / 轻确认），不要停在含糊的「已保存」。
3. **学员路径极短。** 学员端从打开链接到约成 ≤ 3 次点击（日期 → 时间 → 确认）。任何多出来的引导页、注册墙、装饰插画都直接伤害 R1（见 `mvp.md` §2.2）。
4. **老师少点、系统多干。** 自动结算、冲突过滤、流水追溯——界面只露出老师必须做决定的地方（待处理三动作、课时调整语义二选一）。
5. **数字必须可解释。** 「剩余 N 节」「已约 M 节」旁要有可点进流水或批次的路径；争议场景靠透明，不靠口号。
6. **做减法。** 能用系统控件就用系统控件；P0 不做月视图时间轴、不做花哨图表、不做品牌插画墙。

## 3. 从 Logo 抽出的视觉 DNA

| Logo 元素 | 产品里的落点 | 不要怎么用 |
|---|---|---|
| 白兔 | App Icon、启动/空状态小插画、成功微动效 | 不要当导航图标集、不要每行列表都带兔子 |
| 绿日历顶栏 + 大绿勾 | **主色 / 成功 / 完成**；Today 完成课、约成确认 | 不要大面积铺绿底正文页（易吵、易像工具滥绿） |
| 黄铅笔 + 火花 | **创造/编辑强调**：代约、续课、添加学员；成功时的极短 spark | 不要当错误色、不要大面积填充 |
| 粉颊 / 耳内粉 | **温暖点缀**：头像占位、轻提示底、空状态腮红感 | 不要当主按钮、不要大面积粉背景 |
| 大圆角、无硬描边 | 卡片、按钮、日历格、输入框统一大圆角 | 不要直角卡片 + 粗黑描边「贴纸风」 |
| Logo 黑底 | **仅品牌展示**（官网/宣传） | App 内默认浅色工作面，不拿纯黑当日常背景 |

## 4. 色彩

语义优先于色号。实现可用 Asset Catalog / CSS 变量；下列为 **Light 默认**（MVP）。Dark Mode 可后补，但命名先留语义位。

### 4.1 品牌与语义色

| Token | Hex（约） | 用途 |
|---|---|---|
| `brand.green` | `#10A050` | 主操作、完成勾、今日强调、成功 |
| `brand.green.pressed` | `#0C8A44` | 主按钮按压 |
| `brand.green.soft` | `#E6F6EE` | 成功底、选中日浅底、完成行轻背景 |
| `accent.yellow` | `#F8C020` | 次强调：添加/续课图标点缀、spark |
| `accent.yellow.soft` | `#FFF6D6` | 提醒条、弱高亮 |
| `accent.blush` | `#F8B0A8` | 空状态、头像占位暖色 |
| `accent.blush.soft` | `#FDEEEE` | 极轻提示底 |

### 4.2 中性色（Things 式纸感，略暖）

| Token | Hex（约） | 用途 |
|---|---|---|
| `bg.app` | `#F7F6F3` | 页面底（微暖灰，不是纯 `#FFFFFF`） |
| `bg.elevated` | `#FFFFFF` | 卡片、列表行组、Sheet |
| `bg.grouped` | `#EFEDE8` | 分组列表外的凹槽感（可选） |
| `ink.primary` | `#1C1B19` | 主文案 |
| `ink.secondary` | `#6F6B63` | 次要说明、时间元数据 |
| `ink.tertiary` | `#9A958C` | 占位、禁用说明 |
| `line.hairline` | `#E6E2DA` | 分割线（宁淡勿粗） |
| `state.danger` | `#D94841` | 破坏性：删除账号、扣课时确认 |
| `state.warning` | `#C98500` | 逾期改期/迟到取消前提示（可与黄软底搭配） |

### 4.3 使用规则

- **一个屏幕一个主绿动作。** 其余用次要按钮（描边或灰色文字按钮）。
- **红极少用。** 只用于不可逆或扣钱（课时）确认。
- **黄不承担「警告」主角**——警告用 `state.warning` 文案 + 软底；黄留给「在写课表」的创造感。
- 学员端 Web 在微信里：对比度按 WCAG AA；绿按钮白字需确认对比足够（`#10A050` on white 正文不拿绿当小字色）。

## 5. 字体与排版

### 5.1 字体栈

| 端 | 字体 | 说明 |
|---|---|---|
| 老师端 iOS | **SF Pro**（系统） | 精致感来自层级与间距，不来自定制字体 |
| 学员端 Web | `system-ui, -apple-system, "PingFang SC", "Segoe UI", sans-serif` | 微信内置浏览器优先系统字体，加载快、字形熟 |

> Jelly Rabbit 官网的 Clash Display **不进** Rabbit 产品 UI。产品与工作室站点可以气质相关，字体体系分开。

### 5.2 字号阶梯（iOS 参考，Web 同比）

| Role | Size / Weight | 例 |
|---|---|---|
| Large Title | 28–34 Bold | 「今天」 |
| Title | 20–22 Semibold | 学员名、课程名标题 |
| Body | 16–17 Regular | 列表主行 |
| Subhead | 15 Semibold | 分组头「待处理」 |
| Callout / Meta | 13–14 Regular | 时间、剩余课时 |
| Caption | 11–12 Regular | 流水辅助、法律/次要链接 |

**数字：** 课时、时间用略强调的 weight（Semibold）或等宽数字（`monospacedDigit`），扫一眼能对齐。

**中文：** 避免全大写英文装饰；老师端 UI 文案默认中文（与 `mvp.md` 一致）。

## 6. 空间、圆角、层级

| Token | 值 | 用途 |
|---|---|---|
| Space xs–xl | 4 / 8 / 12 / 16 / 24 / 32 | 间距只走这套 |
| Radius.sm | 10 | 小按钮、标签 |
| Radius.md | 14 | 列表内控件、输入框 |
| Radius.lg | 18–20 | 卡片、主按钮、日历格 |
| Radius.pill | 999 | Capsule 标签（状态） |

**阴影：** Things 式——极轻或靠底色分层，不靠厚投影。推荐：

- 卡片：`Y=1–2, Blur=8–12, opacity ≈ 0.06` 暖黑  
- 或无阴影，只用 `bg.app` vs `bg.elevated` 区分  

**安全边距：** 水平 16；列表用系统 `List`/`InsetGrouped` 时尊重系统边距，不要再套一层「双边距卡片海」。

## 7. 组件约定

### 7.1 导航

**老师端：** 底部 4 Tab——`今天` / `日历` / `学员` / `我的`。选中态用 `brand.green`，未选中 `ink.tertiary`。图标用 SF Symbols（日历、人物、人圆等），**不要用兔子剪影当 Tab 图标**。

**学员端：** 底部仅 2 项——`我的课` / `预约`。Profile 放右上角文字或小人标，弱化。微信内注意底部安全区；Tab 不要做成 App 下载引导。

### 7.2 列表行（核心组件）

一行信息优先级（从左到右 / 从上到下）：

1. 时间或姓名（主）  
2. 课程名（次）  
3. 剩余课时 / 状态胶囊（右或第二行）  

整行可点；右侧不堆三个图标按钮。破坏性操作进 Detail，不进滑动里藏三个动作（最多 1 个常用滑动：「完成」）。

### 7.3 「下一节」卡片

Today 与学员首页各一处。白底大圆角；上方小标签「下一节」；主信息时间+人/课；底部一条主按钮（老师：「开始处理 / 查看」；学员：「改期」弱、「预约下一节」强——按场景二选一，避免双主按钮）。

### 7.4 完成控件

- 完成课程：主按钮「完成课程」→ 成功后行内或 Toast 出现 **绿勾**，可伴极短黄色 spark（≤ 400ms，可关减少动效）。  
- 日历上「有课 / 可约」用绿点或绿软底，避免彩虹多色点。

### 7.5 按钮

| 类型 | 样式 |
|---|---|
| Primary | 绿底白字，圆角 lg，高度 ≈ 50 |
| Secondary | 白底绿字或浅灰底 |
| Tertiary | 纯文字 `ink.secondary` |
| Destructive | 文字红或红软底，确认用系统 `confirmationDialog` |

主按钮文案用动词：`完成课程` `确认预约` `发送邀请`，不用 `提交` `OK`。

### 7.6 状态胶囊

小 Pill：`Upcoming` 中性灰字；`待处理` 黄软底；`已完成` 绿软底；`已取消` 灰。文案中文，与状态机一致。

### 7.7 空状态

结构：短标题 + 一句原因/下一步 + 一个主动作。  
可选：小型 logo  deriv（兔+勾）单色或低饱和，**不要大插画故事页**。

示例（老师 Today 无课）：

> 今天没有课  
> 下一节在周三 15:00 · 小陈  
> [查看日历]

### 7.8 Sheet / 表单

创建学员、代约、续课用 sheet 或 push；一屏一事。课时「调整到指定值」必须两个显式选项（购买量记错 / 消耗记错），与 `mvp.md` §12 一致——**这是 UX 硬约束，不是文案修饰**。

### 7.9 学员预约三步

1. **日期：** 仅高亮有 slot 的日期；无 slot 日置灰不可点。  
2. **时间：** 单列时间列表，已占用不展示原因（只表现为不可约）。  
3. **确认：** 课程 / 日期 / 时间 / 老师四行摘要 + 主按钮；逾期规则提示用 warning 软条，确认前可见。  

成功页：绿勾 +「预约成功」+ 时间摘要 +「完成」回首页。不自动跳广告、不求评价。

## 8. 动效

| 场景 | 行为 |
|---|---|
| 页面转场 | 系统默认 push / sheet |
| 完成 / 约成 | 勾出现：轻微 scale 1.0←0.92 + fade，可选 1–2 个黄 spark |
| 列表刷新 | 系统 `refreshable` |
| Tab 切换 | 无弹跳吉祥物 |

原则：**动效表达状态，不表演品牌。** 尊重 iOS「减少动态效果」。

## 9. 老师端关键界面（映射 `mvp.md` §16.1）

| 页面 | UX 要点 |
|---|---|
| **T01 今天** | 最上：日期 + 今日节数；中：「下一节」卡；下：列表，**待处理置顶分组**（视觉用 warning 软底分组头）。空态落到「下一次课」。 |
| **T02 日历** | 周切换器克制；日行显示「N 节课 · M 个可约」；点日进当日列表。P0 不做时间轴月视图。 |
| **T03 Booking Detail** | 状态决定底部动作组；Upcoming 主按钮=完成；危险动作进菜单。撤销完成仅 Completed 且 7 天内展示。 |
| **T05–T07 学员** | 列表右上「剩余课时」对齐扫读；未绑定用 blush 软标「未绑定」。添加流：姓名 → 课 → 课时 → 出邀请，结束在「分享链接」。 |
| **T06 课包** | 批次 `remaining / purchased` 一目了然；摘要行「剩余 N · 已约 M」。流水用时间倒序等宽数字。 |
| **T08–T11 设置** | 分组列表；规则页把「会扣学员钱」的项（免费取消期限、自动结算）写进人话 + 短例。 |

Onboarding（§10.1）：**先加一个真实学生跑起来**，界面文案与步骤计数不要暗示「先导入全部学员」。

## 10. 学员端关键界面（映射 `mvp.md` §16.2）

| 页面 | UX 要点 |
|---|---|
| **S05 邀请** | 首屏极快：老师名 + 课 +「接受邀请」。无下载 App、无「请用 Safari」。接受后进「我的课」，URL replace 为 `/`。升级账号入口弱化。 |
| **S01 我的课** | 一课一卡：课名、剩余 N 节、下一节时间；主 CTA「预约课程」。匿名仅一位老师。 |
| **S02 预约** | 三步，无多余故事页。错误 `SLOT_TAKEN` 用人话：「这个时间刚被约走了，换一个吧」。 |
| **S03–S04** | Upcoming / History；改期/取消前对迟到规则明示。 |

**微信约束：** 不依赖 Service Worker / 推送 / 加主屏；触控热区 ≥ 44pt；避免 `100vh` 裁切，优先 `dvh` 或安全区 padding。

## 11. 文案语气

- 短、具体、可执行。像靠谱助手，不像营销号。  
- 课时是钱：涉及扣课用「将计为一次课程」这类明确句，不用俏皮话稀释。  
- 品牌俏皮仅限：空状态一句、成功页半句。例如成功页可以用「约好了」——但确认扣费句必须严肃。  

| 场景 | 推荐 | 避免 |
|---|---|---|
| 约成 | 预约成功 · 周六 15:00 | 耶！兔子记住啦！！ |
| 迟到取消 | 此次取消将计为一次课程 | 哎呀手慢了哦~ |
| 待处理 | 有 2 节待处理 | 别忘了打卡呀 |

## 12. Logo 与品牌资产

- **App Icon：** 使用官方构图（兔 + 绿历 + 勾 + 笔）；勿在图标上再叠「Rabbit」字标（iOS 图标下已有名）。  
- **应用内：** 默认不在导航栏常驻完整 Logo；`我的` 页可放小标 + 版本号。  
- **通知：** 用 App Icon；文案不提兔子人设。  
- **深色宣传底** 仅用于官网/商店截图背景；App 内截图应展示浅色工作面，避免评审误以为产品是黑底。

---

## 13. Do / Don’t（速查）

**Do**

- 大留白、一层主绿、列表扫读优先  
- 完成态给绿勾；创造入口可点黄缀  
- 学员三步约课；老师待处理集中决策  
- 课时调整语义让老师显式选择  

**Don’t**

- 全页绿渐变、彩虹标签、卡通导航  
- 学员端加注册墙、装 App 引导、第四个 Tab  
- 用黄色当错误色；用兔子解释扣课规则  
- 为「精致」叠双阴影、玻璃拟态、自定义奇形按钮

## 14. 落地清单（给实现）

1. iOS：建立 Color / Type / Radius token（Asset 或 Swift enum），Tab 选中色 = `brand.green`。  
2. Web：`:root` CSS 变量与上表对齐；组件库（若有）只消费 token。  
3. 关键路径先贴合本规范再开视觉细节：T01 待处理、S02 三步、T06 课时调整二选一。  
4. 商店截图与空状态如需插画，单独开品牌衍生，不阻塞 P0。
